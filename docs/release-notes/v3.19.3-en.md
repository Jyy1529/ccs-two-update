# CC Switch v3.19.3 (Fork Release)

> This is a Windows manual-install release of `Jyy1529/ccs-two-update`. It completes the Provider feature-scope controls and DeepSeek/Pi MCP and Skills persistence work.

**[中文版 →](v3.19.3-zh.md) | [日本語 →](v3.19.3-ja.md)**

## Highlights

- Added independent Provider feature scopes for local-proxy retry, Codex agent-role routing, and Codex approval routing, including application-level gates.
- Persisted DeepSeek/Pi MCP and Skills enable states in schema v17; MCP entries are synchronized to each app's own `mcp.json`, while Skills state remains a separate database field.
- Added DeepSeek/Pi directory selection, reset-to-default actions, localized copy, MCP checkboxes, and Skills import state handling.
- DeepSeek/Pi Provider forms now use the documented flat `baseUrl` / `apiKey` / `model` JSON shape instead of Claude `env/config` or unsupported Universal Provider flows.
- Codex role-routing listener validation now accepts only strict loopback IP literals and rejects wildcard, remote, and malformed values.

## Verification

- `pnpm typecheck` and `pnpm format:check`: passed.
- Focused frontend regressions for DeepSeek/Pi forms, MCP, directories, and feature scopes: passed.
- `cargo fmt --check` and `cargo clippy --all-targets --all-features -- -D warnings`: passed.
- Rust library and the selected integration suites: passed (see `docs/handoff-gpt55-report.md`).

## Windows release conditions

- MSI and NSIS installers for Windows `x86_64` are manual-download artifacts only.
- The installers are not Authenticode signed; Windows may display an unknown publisher prompt.
- No Tauri updater artifact, `.sig`, or `latest.json` was generated. In-app automatic updates are unavailable, and this fork no longer points at the upstream update channel.
- Verify the SHA-256 values listed on the GitHub Release page. A real install/upgrade was not run on the development host because it already contains CC Switch installations; use Windows Sandbox or a VM for that check.
